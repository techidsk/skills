# 编码与命名

目标：读调用处就能知道一个函数做什么、是否异步、是否可能失败；注释只承载代码表达不了的约束；类型系统不被绕开。
`project/*` 规则、`@typescript-eslint` 与 `max-lines` 已强制的细节不在此复述，本文写工具判断不了的部分。

## 文件与标识符

- 文件名 `kebab-case`（组件文件也是，如 `user-card.tsx`）。**为什么**：大小写不敏感的文件系统（macOS/Windows）上，`UserCard.tsx` 与 `userCard.tsx` 的改名不会被 git 与 CI 稳定识别。
- 变量与函数 camelCase，类型与接口 PascalCase，标识符用英文。
- 同一目录下需要区分运行环境时才加 `-client` / `-server` 后缀。

## 命名动词表

函数名以调用方要完成的动作开头，接领域对象。主词让调用处读出行为：异步还是同步、会不会副作用。

| 主词 | 调用处应读出的行为 | 收敛掉的同义词 |
| --- | --- | --- |
| `load` | 异步读取一个对象或聚合；缺失用返回类型里的 `null`/结果类型表达 | fetch、find、read、lookup、单值 query |
| `list` | 异步读取集合或分页 | 集合 query |
| `get` | 从已有值同步取出或简单派生 | pick |
| `resolve` | 同步按规则推导一个值 | compute、derive |
| `build` | 同步组装新对象 | make、compose |
| `parse` | 把内存里的外部输入解析成类型，可失败 | — |
| `normalize` / `format` | 同类型内规整 / 产出展示字符串 | — |
| `to<X>` | 同步转换内存值的类型 | map |
| `is` / `has` / `can` | 同步返回 boolean | check |
| `validate` | 返回校验结果，失败通过结果表达 | check |
| `assert` | 条件不满足即抛错，签名用 `asserts` | guard |
| `create` | 同步工厂，或异步持久化新建（由 `async` 区分） | — |
| `ensure` | 不存在则创建，或经副作用保证达到某状态 | — |

`save`、`update`、`delete`、`enqueue` 等写入动词沿用其含义。

- 主词的同步/异步形态由 `project/verb-io` 检查：`load`/`list` 必须异步，纯计算主词必须同步。需要查库判布尔时，用 `load` 读状态，判断留给同步谓词。
- 同义词收敛由 `project/verb-synonyms` 检查。目的是让全局搜索一个主词就能找到同类行为；工具只看语法，主词语义（`require`、`verify` 等专用动词）由 review 核对。
- 名字里的后缀只补签名看不出的行为保证，如 `BestEffort`（失败不抛）、`ForViewer`（按查看者过滤）。参数类型已表达的上下文不重复（带事务参数就不加 `InTransaction`）。
- 两个函数只有一个取值不同时，写一个函数加明确参数，不写平行函数。
- 保留领域前缀：具名导入的调用处需要它表达对象，也需要它支持全局检索。
- 业务专有词汇（统一用词、禁用词）登记进词汇表和 `project/banned-words` 的 `words`；新增业务概念先在词汇表定英文名。

例外：框架约定的命名（React 的 `use*`/`handle*`/`on*`、路由方法 `GET`/`POST`、框架生成钩子）、测试、第三方 API 按各自约定。实现固有异步接口等无法避免的情况，用附理由的局部 `eslint-disable`。

迁移存量命名时保留对外与持久化合同：HTTP 路径、wire 字段、数据库字段与枚举字面量、深链、CLI 参数不随内部符号改名。

## 注释

**总则**：注释随行为同步更新，只写代码、类型签名与目录约定表达不了、且影响维护决策的信息——外部协议的反直觉事实、兼容性或安全约束、执行顺序、资源所有权、跨模块契约。迁移过程、方案对比与历史妥协写进 Git commit 正文，不进源码。

- 类型、路径、命名已经说明的不复述。常量默认不加注释，只在名称、值、单位、引用关系说不清时补一句。
- 现行约束在它生效的地方写一句；参数含义以声明处为准，不在调用处重复。
- 注释语言按团队约定统一（`{{注释语言}}`）。
- `///` 只用于 TypeScript 指令（`project/no-triple-slash-comment`）。

### Docstring 按层分工

| 层 | 写法 |
| --- | --- |
| 入口薄层与路由私有文件（页面、布局、路由处理器、私有组件） | 默认不写文件级与导出级 docstring |
| 普通函数与模块 | 仅当名称和类型表达不了前置条件、副作用或失败语义时，用 1–3 行 `/** … */`；不逐项写 `@param`/`@returns`。多入口共享的约束写文件头 |
| 公共底座与配置型入口（跨模块封装的工厂、`define*` 一类） | 入口 docstring 写适用场景与取舍、核心选项的判据和最小 `@example`；完整默认值和低频钩子写在 `Options` 接口属性的单行注释里 |

**为什么**：越靠近入口、越私有的代码越不需要注释；越靠近公共底座，调用者越多，说明的回报越高。

## 反 Patch 传染

实现体默认零注释，只有外部平台或协议的反直觉客观事实可以留单行说明。遇到问题时修根因。

**为什么**：为绕过根因的临时 patch 写一段合理化注释，会让后来的人（包括 agent）把它当成标准写法复制扩散。

确因外部第三方阻塞必须临时绕行时，把绕行收进唯一的底层适配处，并标注：

```ts
// FIXME(#123): 临时绕过 xxx 的 yyy 问题，禁止新代码仿写
```

`#123` 是跟踪该问题的 issue；issue 关闭时同步删除绕行。

## 类型安全

- 不用 `any`：定义具体类型，或在源头对齐泛型（`@typescript-eslint/no-explicit-any`）。
- 不用 `as never`：穷尽分支检查用 `satisfies never` 或 `const _x: never = v`（`project/no-as-never`）。
- 不用 `@ts-ignore`：确需压制时写 `@ts-expect-error` 并附说明（`ban-ts-comment` 配置 `allow-with-description`）。**为什么**：`@ts-expect-error` 在问题被修复后会报「未使用」，压制不会悄悄烂在代码里；说明让后来者知道何时能删。
- 外部输入（请求、环境变量、第三方响应）进入业务代码前用 schema 校验收窄成具体类型，不用断言越过。

## 运行时配置与日志

- 运行时配置不硬编码：从项目的配置模块读取（`{{运行时配置入口}}`，落地时填路径）；启动期才需要的环境变量走统一的 env 入口（`{{环境变量入口}}`）。**为什么**：硬编码值改动要重新发布，且各处散落的副本很快不一致。
- 密钥、令牌、地址不进源码，不进日志。
- 服务端日志统一用项目的日志封装（`{{日志入口}}`），不直接 `console.*`；日志带足够的定位上下文（标识、阶段），不打印整个请求体或用户隐私字段。

## 装法

规则文件在 `templates/eslint/`：`naming.mjs`（动词表、禁用词）、`comment-hygiene.mjs`（`as never`、`///`）。注册方式与 options 见 `eslint.config.snippet.mjs`。存量违规先用 `eslint --suppress-all` 冻结再逐步收紧。
