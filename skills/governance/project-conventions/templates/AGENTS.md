# {{项目名}}：项目规则与按需阅读

本文件保留全局约束和任务入口；详细规则与例外在链接的领域文档中维护。路径默认相对本文件所在目录。
开始改动前，按任务行为及涉及领域读取下列命中的文档；跨领域任务读取全部命中项，工作范围扩大时补读。
链接是必须执行的阅读指令，不依赖客户端自动展开。带锚点时读取该节全文及其依赖的定义、例外与必读引用；不遍历未命中文档。

## 授权与数据边界

- 数据库迁移先生成并审阅 SQL，默认由人部署；只有当前对话明确授权并指定环境后才可代执行。共享／生产库禁止会重置或绕过迁移记录的命令。
- 发布、部署、打 tag、推送和合并到受保护分支由人决定；提交本身不构成发布授权。
- 对外接口、已持久化数据和历史任务的兼容语义须保留；改变既有行为前先核对领域合同和发布边界。
- 密钥、令牌与生产数据不写入仓库、日志或对话产物。

## 文件规范

- 文件命名 `kebab-case`；目录同理。
- 单文件超过 800 行时按职责边界拆分；找不到边界时在文件头写明不拆的原因。
- 逻辑默认就近写在唯一调用处；拆到新文件、导出或上移共享层须有当下的理由（第二个调用方、依赖隔离、独立测试、超长后找到的职责边界）。「将来可能复用」不算理由。

## 代码规范

- 变量与函数 `camelCase`，类型与接口 `PascalCase`，均用英文。
- 命名、注释、类型安全、错误处理与日志的细则读 [编码规范]({{文档根}}/agents/coding.md)；新增或修改函数命名时必读其中的命名一节。
- 类型绕行（`any`、`@ts-ignore`）按规范使用，规则以 lint 为准。

## 目录职责

新增页面、功能或业务内容，调整组件、模块、目录、依赖或 service 的职责与归属前，读 [架构约束]({{文档根}}/architecture.md)。

- `{{源码根}}/{{入口薄层目录}}` 只做适配（路由、页面、入口）；业务逻辑进 `{{源码根}}/{{业务模块目录}}`。
- `{{源码根}}/{{基础设施目录}}` 只放与业务无关的基础设施；共享使用本身不构成基础设施。
- 依赖方向：业务模块不依赖入口层；基础设施不依赖入口层与业务模块。方向由 lint／依赖检查强制。

## 测试与交付

决定验证方案，新增、修改、删除测试，以及运行 lint／类型检查／测试／构建及交付前，读
[测试与交付]({{文档根}}/agents/contributing.md#测试与交付)：核心闭环与普通改动分流，先复用已有覆盖、缺口才补测试，
按影响范围选择检查。提交前本地跑 `{{包管理器}} run verify`，它与 CI 的检查一一对应。

## 文档规范

纳入 Git 的文档放 `{{文档根}}/`，按业务域归属；新增文档登记 [`{{文档根}}/README.md`]({{文档根}}/README.md)。
长期文档随实现维护，`archive/` 不作为现状依据。
编写 Spec／PRD、拆任务，或新增、重构、移动、删除文档前，读
[文档规范]({{文档根}}/agents/contributing.md#文档规范)，按其中的仓库／Issue／本地临时材料归属及收尾规则执行。

## Git 规范

用户要求提交、准备版本或发布前，读 [Git 规范]({{文档根}}/agents/contributing.md#git-规范)；仅提交获授权范围。
并行会话共用工作区时，提交按路径限定：`git commit --only -- <paths>`。
修改 hooks、CI 或排查检查失败前，读 [治理检查与交付]({{文档根}}/agents/contributing.md#治理检查)。
告警档检查的告警也要处理；存量基线不是新增违规的许可。
